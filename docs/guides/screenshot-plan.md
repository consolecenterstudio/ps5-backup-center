## Language and theme coverage

Capture each applicable row on TV and web. First establish matched English and French views, then populate the same shot IDs for all 19 app locales: en, fr, fr-CA, es, es-419, pt-BR, pt-PT, de, it, nl, pl, tr, ru, zh-Hans, zh-Hant, ja, ko, vi, ar. Do not imply translated guides or screenshots exist before they do.

Use Night as the consistent reference, OLED for the hero sequence and Light for selected explanatory views. Use the same Settings scene for an eight-theme comparison. Preserve the selected item, scroll position, filter and dataset across language variants. Record theme, locale, app/engine versions, capture date, surface, viewport and whether the image is native, retouched or a mock.

Suggested filenames: `CAP-04.tv.en.oled.png`, `CAP-04.web.fr.light.png`. Keep raw originals outside the public asset tree. Public derivatives must have opaque, flattened replacements for account names, IDs, IPs, hostnames, paths, pairing codes and secrets. Recheck thumbnails, captions, metadata and visible background windows. Avoid blur that leaves readable characters.

## Editorial placement

Use one contextual image beside the relevant guide step rather than an uncaptioned image wall. Each caption states what the reader should notice. A language fallback must show the actual screenshot language. Edited system labels must be identified as edited; they are not proof of a native translated system screen.

## Video sequence

Plan a short product overview and separate focused tutorials: first backup, compare and restore, two consoles, Switch / emulator, NAS depot, web with the TV app closed. Show actual actions only when recorded; a still-image montage is a preview, not a runtime demonstration. Keep app audio and any separately composed soundtrack identified in the production notes. Creator outreach and publishing remain pending authorisation.
