# For developers

Find the architecture and contribution references.

## Where to find it

TV: Settings › Diagnostic and about / Acknowledgements. Use L1/R1 for tabs; open the gear for Settings.

Web: the corresponding spaces in the paired browser navigation; use buttons and checkboxes.

## Steps

1. The engine serves the API and web UI, owns scanning, copy work and persistent task journals. TV and browser are clients of the same engine.
2. Read the contribution guide before building. Use its current build commands and toolchain requirements; distinguish a Mac preview from a console runtime test.
3. Read FEATURES for the TV / web and validation matrix; PLAN records decisions. changelog.json is the release-history source.
4. For translation work use engine/web/i18n catalogues, preserve placeholders and check text fit, CJK and Arabic direction. For a new feature plan both clients together.
5. API reference generation, authenticated examples and reproducibility verification remain separate documentation work; do not treat this overview as an API contract.

## Safety and attention

Close the affected game or app before restoring, replacing or moving it. Check account, direction and destination; read confirmations and keep an independent copy of important data. Verification and safety copies reduce risk without providing an absolute guarantee.
